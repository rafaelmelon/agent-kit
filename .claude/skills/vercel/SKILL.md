# Skill: Vercel

Access Vercel deployments, logs, and environment variables using the `vercel` CLI.

## When to use

- Checking deployment status after a push
- Reading production or preview build logs
- Inspecting or updating environment variables
- Triggering a manual deploy

## Prerequisites

- `vercel` CLI installed: `npm i -g vercel`
- Authenticated: `vercel whoami`
- Linked to project: `vercel link` (run once per project)

## Key operations

### Deployments

```bash
# List recent deployments
vercel list

# Get deployment details
vercel inspect <deployment-url>

# Deploy manually (production)
vercel --prod

# Deploy preview
vercel
```

### Logs

```bash
# Stream logs for the latest production deployment
vercel logs --follow

# Logs for a specific deployment
vercel logs <deployment-url>
```

### Environment variables

```bash
# List env vars for a project
vercel env ls

# Add an env var
vercel env add MY_VAR production

# Pull env vars to local .env.local
vercel env pull .env.local
```

## Notes

- Never commit `.env.local` or any file generated by `vercel env pull`.
- Use `vercel env pull` only for local development, not for CI/CD secrets.
- For build errors, check logs via `vercel logs` before digging into code.
